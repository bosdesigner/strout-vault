# Search performance: EXPLAIN ANALYZE on 400k segments

Generated by `npm run db:bench` on 2026-10-21 against a local PostgreSQL 16.15 (Ubuntu 16.15-0ubuntu0.24.04.1)
with **400,800 segments** across 1,200 recordings (production has 396,956 across 1,186).
The query is exactly the one `server/services/search.ts` runs: one GIN probe with
`tsv @@ websearch_to_tsquery('english', $1)`, grouped per recording and ranked by the best `ts_rank`,
paginated by group (20 per page); only the three lines shown per group go through `ts_headline`.

| query | groups on page 1 | wall time (endpoint, warm) | EXPLAIN execution time |
|---|---|---|---|
| `permit schedule` | 20 | 21.9 ms | 36.363 ms |
| `"copper gutter"` | 20 | 25.3 ms | 29.498 ms |
| `skylight OR dormer` | 20 | 89.5 ms | 92.456 ms |
| `shutter -cedar` | 20 | 71.1 ms | 65.672 ms |
| `permit` | 20 | 51.0 ms | 53.676 ms |
| `contractor invoice` + {"workspaceId":"strout_arch","from":"2024-01-01","to":"2025-12-31"} | 20 | 22.4 ms | 20.458 ms |
